# Portra C 模块最终回归与体验稳定化记录

> 更新日期：2026-07-09  
> 范围：消息列表、聊天详情、订单页、作品相册、路由 chunk、演示预热说明。

## 本轮目标

本轮不是新增交易功能，也不是大规模重构。目标是补上最终演示前的性能与交互体验检查：页面进入要有即时反馈，已有数据不应因为后台刷新被清空，消息图片要保持本地即时预览，作品相册缩略图不应重复请求或闪烁。

## 已处理项

| 页面 / 模块 | 调整 | 影响 |
|---|---|---|
| `/messages` | 远端会话和订单返回后先渲染基础会话列表，再后台补齐最新消息和报价 preview | 减少列表首屏等待完整 hydrate 的时间 |
| `/messages/:conversationId` | 命中缓存时先展示缓存消息、报价和订单工作台，再后台刷新 | 避免进入聊天详情时已有内容被清空 |
| `/orders` | 订单列表与摄影师邀请并行请求；订单详情附属数据并行请求 | 降低订单切换和详情打开等待时间 |
| `/orders/:orderId/deliveries/:deliveryId` | 缩略图逐张显示；避免父页面和网格重复下载；修正 objectURL 清理时机 | 减少相册卡顿、重复请求和预览闪烁 |
| 路由 | 消息、订单、作品相册相关页面改为路由级 `React.lazy` | 降低核心工作流页面对主路由首包的压力 |
| 文档 | `DEMO_GUIDE.md` 新增性能与体验验收说明 | 明确 chunk warning、冷启动、网络慢和演示预热的区分方式 |

## 已确认的体验原则

- 会话列表和聊天详情采用 stale-while-revalidate，不把后台刷新做成整页白屏。
- 图片消息发送仍保留 optimistic 本地 preview，远端文件可用后再替换。
- 文件附件仍以轻量文件卡展示，发送失败保留内容并提供重试。
- 订单页时间线和后续事项仍保持上一轮视觉验收结果，不回退为条状背景或说明书式卡片。
- 补款、多附件批量发送、复杂订单仲裁表单继续暂缓。

## 仍需后续关注

- 会话列表 preview 仍需要逐会话补齐消息和报价摘要，历史会话很多时建议后端提供列表级 latest message / latest quote 字段。
- 聊天详情未做消息虚拟列表或历史分页，超长会话未来可能需要增量加载。
- Vite chunk warning 可能仍存在，后续可以结合 `manualChunks` 拆分 MUI、图标库和非首屏页面。
- 线上首开慢需要区分前端 chunk、后端冷启动和图片/附件下载，不应只看单次体感下结论。
