# Portra 约拍平台 — 本地运行与完整演示说明

 
> 对应分支：`main`  
> 最后更新：2026-06-07  
> 说明：本说明以仓库当前代码为准，重点覆盖消息、报价、订单、作品交付、返修、展示授权、评价与申诉。演示时优先使用真实注册账号现场操作，避免只依赖历史测试数据。

---

## 一、环境要求

| 依赖    | 要求 | 说明                                    |
| ------- | ---- | --------------------------------------- |
| Java    | 17   | `java -version` 确认                    |
| Maven   | 3.8+ | 仓库内置 `mvnw`，也可直接使用本机 Maven |
| Node.js | 18+  | `node -v` 确认                          |
| MySQL   | 8.0  | 需提前启动服务并建好数据库              |

---

## 二、数据库初始化

启动 MySQL 后执行：

```sql
CREATE DATABASE IF NOT EXISTS camera_app
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

建表脚本在 `backend/src/main/resources/db/V1_baseline.sql`。项目启动时不会自动执行，首次演示前需要手动运行一次：

```bash
mysql -u root -p camera_app < backend/src/main/resources/db/V1_baseline.sql
```

如果已经建过表，可以跳过这一步。若表结构与代码不一致，建议清空演示库后重新导入脚本。

## 三、启动后端

```bash
cd backend
mvn spring-boot:run
```

看到类似下面日志说明启动成功：

```text
Started CameraApplication in xx.xxx seconds
```

后端运行在 `http://localhost:8080`。

邮件配置说明：后端已内置 QQ SMTP 配置，注册时验证码直接查收即可；若收不到邮件，先看后端日志和垃圾邮件箱。

## 四、启动前端

新开一个终端：

```bash
cd frontend
npm install
npm run dev
```

看到以下日志说明启动成功：

```text
Local:   http://localhost:5173/
```

浏览器打开 `http://localhost:5173`。

## 五、注册演示账号

演示至少需要两个账号：一个客户（单主），一个摄影师。建议用两个可收邮件的邮箱现场注册。

1. 打开 `http://localhost:5173/login/register`。
2. 输入邮箱，点击获取验证码，查收 6 位验证码。
3. 设置昵称和密码，完成注册。
4. 第一个账号保留客户身份，用于发布需求、确认报价、支付、确认作品、返修、评价、处理授权。
5. 第二个账号登录后进入个人主页，切换到摄影师身份，保存摄影师资料，再发布服务橱窗。

摄影师资料保存很重要：它会初始化摄影师档案，后续服务橱窗、信用分、昵称展示都会依赖它。

## 七、主路径 A：从摄影师服务橱窗发起约拍

前置条件：摄影师已经发布一个在线服务橱窗；客户已登录。

| 步骤 | 操作账号 | 前置状态       | 页面入口            | 用户动作                             | 预期页面表现                             | 业务状态变化                         | 评审讲解点                                   |
| ---- | -------- | -------------- | ------------------- | ------------------------------------ | ---------------------------------------- | ------------------------------------ | -------------------------------------------- |
| 1    | 客户     | 摄影师橱窗在线 | 约拍大厅 → 橱窗大厅 | 点击橱窗卡片或查看橱窗               | 进入橱窗详情，展示作品、价格、摄影师信息 | 无订单变化                           | 橱窗是服务展示，不等于订单                   |
| 2    | 客户     | 已打开橱窗详情 | 橱窗详情 / 卡片按钮 | 点击现在预定或发起咨询               | 跳转消息沟通页                           | 创建或进入与摄影师的沟通             | 服务包预约当前进入沟通，不等于支付           |
| 3    | 双方     | 已进入沟通     | 消息详情页          | 用文字确认时间、地点、成片数量、用途 | 中间聊天流出现普通消息                   | 暂未生成订单                         | Portra 的交易从沟通开始，而不是直接下单      |
| 4    | 摄影师   | 沟通确认方案   | 消息页报价入口      | 发送正式报价                         | 聊天流出现报价卡，右侧工作台显示报价摘要 | 报价进入待客户确认                   | 报价是业务对象，会生成订单，不是普通聊天消息 |
| 5    | 客户     | 报价待确认     | 报价卡 / 右侧面板   | 查看报价详情，确认或拒绝             | 可看到完整报价内容                       | 确认后生成待支付订单；拒绝则继续沟通 | 报价确认是订单生命周期入口                   |

需要强调：橱窗里展示的价格和档期只是服务范围。真正进入平台担保，必须先由摄影师发正式报价，再由客户确认报价生成订单。

## 八、主路径 B：从需求大厅发起约拍

前置条件：客户已发布需求；摄影师已登录。

| 步骤 | 操作账号 | 前置状态   | 页面入口                    | 用户动作                                                         | 预期页面表现                 | 业务状态变化       | 评审讲解点                                 |
| ---- | -------- | ---------- | --------------------------- | ---------------------------------------------------------------- | ---------------------------- | ------------------ | ------------------------------------------ |
| 1    | 客户     | 无需求     | 发布需求页                  | 填写标题、拍摄类型、城市、地点、预算、时间描述、时间标签、参考图 | 需求预览显示预算、城市、时间 | 需求为开放中       | 需求用于让摄影师响应，不直接产生订单       |
| 2    | 摄影师   | 需求开放中 | 约拍大厅 → 需求大厅         | 点击我来响应                                                     | 按钮变为已响应               | 生成需求响应记录   | 一键响应只提交意向，不会立即创建沟通       |
| 3    | 客户     | 收到响应   | 个人主页 / 需求响应相关入口 | 查看摄影师响应，接受其中一个                                     | 可进入与该摄影师的沟通       | 被接受响应关联沟通 | 客户选择摄影师后，才进入报价协商           |
| 4    | 摄影师   | 沟通已建立 | 消息页                      | 根据需求发送正式报价                                             | 报价卡出现在聊天流           | 报价待客户确认     | 需求路径后续复用报价、订单、支付、交付闭环 |
| 5    | 客户     | 报价待确认 | 消息页                      | 确认报价                                                         | 生成订单，进入待支付         | 订单为待支付       | 从需求到订单，关键节点仍是确认报价         |

未被接受的响应不会进入后续订单流程。客户接受某个响应后，后续流程与服务橱窗路径一致。

## 九、报价与沟通演示

### 摄影师发送报价

前置条件：双方已有沟通，且当前没有待确认报价和已生成订单。

摄影师在消息页点击报价入口，填写：报价金额、拍摄地点、拍摄开始时间、拍摄结束时间、最晚交付日期、原片数量、精修数量、照片使用范围、服务内容、备注说明、订单条款。

预期结果：

| 页面位置   | 预期表现                                                       |
| ---------- | -------------------------------------------------------------- |
| 聊天流     | 出现摄影师发送报价的卡片                                       |
| 右侧工作台 | 显示报价金额、地点、使用范围等摘要                             |
| 客户视角   | 可以打开报价详情，只能确认或拒绝，不能修改报价                 |
| 摄影师视角 | 待确认报价可编辑；如果被拒绝，可以带入旧内容重新发送一份新报价 |

讲解点：系统限制同一沟通里不能同时存在多份待确认报价，避免客户确认错版本。

### 客户查看报价

客户点击报价卡片，检查金额、拍摄时间段、地点、服务内容、原片/精修数量、使用范围、备注和条款。客户不能改报价，只能接受或拒绝。

### 客户拒绝报价

| 步骤 | 操作账号 | 用户动作         | 预期页面表现                         | 业务状态变化       | 讲解点                                 |
| ---- | -------- | ---------------- | ------------------------------------ | ------------------ | -------------------------------------- |
| 1    | 客户     | 点击拒绝报价     | 报价卡变为已拒绝，聊天流出现拒绝记录 | 报价状态变为已拒绝 | 拒绝报价不是取消订单，因为订单还没生成 |
| 2    | 双方     | 继续沟通         | 可继续发送文字消息                   | 沟通继续存在       | 拒绝后双方仍可协商新方案               |
| 3    | 摄影师   | 点击重新发送报价 | 打开报价表单并带入上一份内容         | 保存后创建新的报价 | 当前实现是新建报价，不是修改已拒绝报价 |

### 客户确认报价

| 步骤 | 操作账号 | 用户动作     | 预期页面表现                                   | 业务状态变化                      |
| ---- | -------- | ------------ | ---------------------------------------------- | --------------------------------- |
| 1    | 客户     | 点击确认报价 | 提示报价已确认，订单已生成                     | 报价变为已确认                    |
| 2    | 平台     | 自动创建订单 | 右侧工作台出现订单进度，聊天流出现订单生成提示 | 订单进入待支付（PENDING_PAYMENT） |
| 3    | 双方     | 查看订单     | 可从消息页跳到订单页                           | 订单与沟通绑定                    |

## 十、订单支付与平台担保演示

前置条件：客户已经确认报价，订单处于待支付。

| 步骤 | 操作账号 | 页面入口                  | 用户动作         | 预期页面表现               | 业务状态变化                                    | 讲解点                         |
| ---- | -------- | ------------------------- | ---------------- | -------------------------- | ----------------------------------------------- | ------------------------------ |
| 1    | 客户     | 消息页右侧工作台 / 订单页 | 点击支付         | 弹出或触发模拟支付         | 待支付 → 已支付，等待拍摄（PAID_PENDING_SHOOT） | 只有客户能支付，摄影师不能代付 |
| 2    | 平台     | 支付成功后                | 自动写入支付记录 | 页面提示资金已进入平台担保 | 资金状态为平台托管中                            | 钱没有直接给摄影师             |
| 3    | 双方     | 消息页和订单页            | 刷新或等待同步   | 两处都显示已支付、等待拍摄 | 状态同步                                        | 消息页和订单页是同一条交易进度 |

订单状态中文说明：

| 中文状态         | 技术状态                  | 含义                                         |
| ---------------- | ------------------------- | -------------------------------------------- |
| 待支付           | PENDING_PAYMENT           | 客户已确认报价，但还没付款                   |
| 已支付，等待拍摄 | PAID_PENDING_SHOOT        | 资金已进入平台担保，等待约定拍摄时间         |
| 拍摄中           | SHOOTING                  | 已到约定拍摄时间段                           |
| 等待上传作品     | PENDING_DELIVERY          | 拍摄结束，等待摄影师上传作品                 |
| 作品待确认       | DELIVERED_PENDING_CONFIRM | 摄影师已上传作品，等待客户确认或返修         |
| 返修中           | REWORK_REQUIRED           | 客户要求返修，等待摄影师重新上传             |
| 已完成           | COMPLETED                 | 客户确认或系统自动确认，担保资金结算给摄影师 |
| 已取消           | CANCELLED                 | 未支付订单取消结束                           |
| 已退款           | REFUNDED                  | 已支付订单退款结束                           |
| 争议处理中       | APPEALING                 | 订单处于争议处理状态，正常动作暂停           |

## 十一、订单取消与退款演示

### 待支付订单取消

前置状态：客户确认报价后，尚未支付。

| 操作账号 | 页面入口              | 用户动作                 | 预期结果                                   |
| -------- | --------------------- | ------------------------ | ------------------------------------------ |
| 客户     | 消息页工作台 / 订单页 | 点击取消待支付订单并确认 | 订单变为已取消，不产生担保资金，不产生退款 |
| 摄影师   | 消息页 / 订单页       | 查看状态                 | 看到订单已取消，后续履约动作不可用         |

当前代码限制：待支付订单只有客户可以取消。

### 已支付但拍摄前取消并退款

前置状态：订单已支付，且当前时间早于拍摄开始时间。

| 操作账号 | 页面入口              | 用户动作           | 预期结果                             |
| -------- | --------------------- | ------------------ | ------------------------------------ |
| 客户     | 消息页工作台 / 订单页 | 点击取消并申请退款 | 订单变为已退款，平台担保资金退回客户 |
| 平台     | 后端                  | 更新退款和支付记录 | 资金状态变为已退款，不结算给摄影师   |

当前代码限制：只有客户可以在拍摄开始前取消已支付订单。到了拍摄开始时间后，前端会提示不能走这个普通取消退款入口。

### 超过最晚交付日期未交付自动退款

前置状态：订单已支付，拍摄已结束，到了最晚交付时间仍没有上传作品。

系统行为：后端定时任务会自动扫描，超过最晚交付时间且未上传作品的订单会自动退款并结束订单。

演示方式：现场不建议等待真实时间。可以选择已有对应状态订单展示，或结合后端定时任务说明：该流程由 `OrderAutoConfirmScheduler` 定时触发，不是客户手动退款按钮。

## 十二、拍摄阶段与时间感状态演示

Portra 的拍摄状态不是让摄影师随便手动推进，而是围绕报价里的拍摄开始时间和结束时间展示时间感状态。

| 时间点           | 页面表现                                                             | 状态/动作                |
| ---------------- | -------------------------------------------------------------------- | ------------------------ |
| 支付后、拍摄前   | 显示等待拍摄，并展示约定时间段                                       | 订单保持已支付，等待拍摄 |
| 到达拍摄时间段   | 页面提示按约定拍摄中，消息页/订单页会定时同步                        | 后端任务可推进到拍摄中   |
| 拍摄结束后       | 摄影师看到上传作品入口                                               | 页面进入等待交付语义     |
| 摄影师上传作品时 | 如果状态还停在已支付或拍摄中，后端会自动补齐到待交付再进入作品待确认 | 避免摄影师手动点中间状态 |

演示时如果不能等待真实时间，可以选择已有不同状态订单展示，也可以在报价时把拍摄时间设置得接近当前时间，方便观察页面刷新。

## 十三、作品交付、返修与重新交付演示

### 摄影师上传作品

前置状态：订单已到交付阶段，或拍摄时间已经结束。

| 步骤 | 操作账号 | 页面入口              | 用户动作               | 预期页面表现                                 | 业务状态变化         |
| ---- | -------- | --------------------- | ---------------------- | -------------------------------------------- | -------------------- |
| 1    | 摄影师   | 消息页工作台 / 订单页 | 选择图片并填写作品说明 | 上传成功提示                                 | 生成作品记录         |
| 2    | 平台     | 后端                  | 保存作品文件和作品批次 | 消息流出现作品卡，订单页作品模块出现最新作品 | 订单进入作品待确认   |
| 3    | 客户     | 消息页 / 订单页       | 点击作品卡             | 进入作品详情页                               | 可查看相册、下载作品 |

当前交付接口一次上传一个文件；前端作品详情会按作品批次展示，可查看历史上传记录。

### 客户查看作品详情

作品详情页支持：缩略图浏览、打开大图预览、选择文件、下载选中、下载全部、返回沟通、返回订单。预览和下载依赖后端文件下载接口，演示时后端必须运行且文件记录可访问。

### 客户提交返修要求

前置状态：订单处于作品待确认。

| 操作账号 | 页面入口                     | 用户动作                             | 预期结果                           |
| -------- | ---------------------------- | ------------------------------------ | ---------------------------------- |
| 客户     | 作品详情页 / 订单页 / 消息页 | 点击提交返修要求，填写原因和修改方向 | 订单进入返修中，消息页出现返修记录 |
| 摄影师   | 消息页 / 作品详情页          | 查看返修提示                         | 看到需要重新上传作品               |

返修说明不能为空。作品详情页限制 500 字，订单页和消息页也会阻止空提交。

### 摄影师重新交付

前置状态：订单处于返修中。

| 操作账号 | 页面入口            | 用户动作     | 预期结果               |
| -------- | ------------------- | ------------ | ---------------------- |
| 摄影师   | 消息页上传作品入口  | 重新上传作品 | 生成新一轮作品记录     |
| 客户     | 消息页 / 作品详情页 | 查看新作品   | 订单重新进入作品待确认 |

返修不能由客户直接改成完成，必须由摄影师重新上传作品推进。

### 客户确认接收作品

客户确认接收后，订单进入已完成，平台担保资金结算给摄影师，页面弹出完成反馈并引导客户评价。

### 自动确认

摄影师上传作品后，如果客户在约定时间内既不确认也不返修，后端定时任务会自动确认完成并结算。现场演示不建议等待 7 天，可通过状态日志和代码逻辑说明。

## 十四、作品详情页与批量下载演示

前置条件：订单已有至少一条作品记录。

## 十五、照片展示授权演示

### 摄影师发起展示授权申请

前置状态：订单已完成，并且存在已交付作品。

| 步骤 | 操作账号 | 页面入口                            | 用户动作                     | 预期结果                     |
| ---- | -------- | ----------------------------------- | ---------------------------- | ---------------------------- |
| 1    | 摄影师   | 订单页展示授权模块 / 消息页授权入口 | 选择已交付作品，填写申请说明 | 生成待客户确认的展示授权申请 |
| 2    | 平台     | 页面同步                            | 在授权记录中展示申请         | 客户可以查看并处理           |

讲解点：摄影师不能默认拿客户作品做客片展示，必须选择作品并获得客户授权。

### 客户查看、同意或拒绝授权

| 分支     | 操作账号 | 用户动作                   | 预期状态                     | 讲解点                             |
| -------- | -------- | -------------------------- | ---------------------------- | ---------------------------------- |
| 查看详情 | 客户     | 打开授权卡片或订单授权记录 | 看到申请作品、用途说明和备注 | 授权粒度是作品文件                 |
| 同意授权 | 客户     | 点击同意                   | 授权状态变为已授权展示       | 摄影师可将这些作品作为真实客片展示 |
| 拒绝授权 | 客户     | 填写拒绝原因并拒绝         | 授权状态变为已拒绝展示       | 摄影师不能展示这些作品             |

### 多次授权

摄影师可以针对同一订单的不同作品再次发起授权申请，每次申请都有独立状态。但同一订单里的同一个作品不能重复申请，后端会拒绝重复授权请求。

这里需要区分两类能力：订单争议状态和评价申诉。

前置条件：自己收到了对方评价。

| 步骤 | 操作账号 | 页面入口                      | 用户动作             | 预期结果                                             |

| 2    | 被评价方 | 评价申诉详情页                | 查看申诉状态         | 可看到原因、关联订单、关联评价和处理结果             |

### 订单争议：当前前端不作为现场手动主路径

## 十八、消息页与订单页联动演示

消息页不是普通聊天页，而是“沟通 + 报价 + 订单进度 + 作品 + 授权”的交易工作台。

| 演示点     | 页面表现                                    | 讲解点                                           |
| ---------- | ------------------------------------------- | ------------------------------------------------ |
| 普通沟通   | 中间聊天流展示文字消息                      | 先沟通方案，再发正式报价                         |
| 报价卡     | 聊天流展示报价卡，右侧显示摘要              | 报价确认后生成订单                               |
| 订单进度   | 右侧工作台显示当前阶段和下一步动作          | 消息页可直接处理支付、取消、上传作品、确认、返修 |
| 作品卡     | 摄影师上传后，聊天流出现作品事件            | 点击进入作品相册页                               |
| 展示授权   | 订单完成后可发起授权申请，客户处理同意/拒绝 | 保护客户作品使用权                               |
| 订单页跳转 | 消息页可点击查看订单                        | 订单页是完整订单档案                             |
| 返回沟通   | 订单页和作品页可返回对应沟通                | 工作台与档案页互相联动                           |
| 自动刷新   | 消息页和订单页有轮询和时间点刷新            | 状态变化会同步到两处                             |

当前普通聊天图片、附件、表情、补款、平台协助等工具按钮不是完整业务入口：图片/附件消息因后端消息接口没有绑定文件字段而禁用，作品必须通过订单上传。

## 二十、需求大厅详细演示

需求大厅是消费者主动发布拍摄需求、摄影师主动浏览并响应的双向匹配模块。

### 20.1 客户发布需求

入口：约拍大厅 → 需求大厅 → 发布需求。

| 字段 | 说明 | 演示建议 |
|---|---|---|
| 需求标题 | 简短说明想拍什么 | 如"毕业纪念照（两人）" |
| 拍摄类型 | 选择场景标签（人像/婚礼/商业等） | 至少选一项 |
| 城市 | 拍摄所在城市 | 选南京或本地城市 |
| 地点描述 | 具体地点补充说明 | 如"玄武湖附近" |
| 预算区间 | 最低和最高预算 | 填写合理区间，摄影师响应时会参考 |
| 时间描述 | 希望拍摄的时间段 | 如"周末上午均可" |
| 时间标签 | 工作日/周末/节假日等 | 辅助摄影师快速筛选 |
| 参考图 | 上传风格参考图片（可选） | 上传一张测试图，展示图片上传能力 |

发布后预期结果：需求状态为"开放中"，需求大厅列表中可搜索到该需求。

### 20.2 摄影师浏览需求大厅

入口：约拍大厅 → 需求大厅（切换到摄影师身份后访问）。

| 演示点 | 操作 | 预期页面表现 |
|---|---|---|
| 浏览列表 | 进入需求大厅 | 显示所有开放中的需求卡片，含标题、城市、预算、时间标签 |
| 查看参考图 | 点击需求卡片 | 进入详情，可预览参考图、查看完整描述 |
| 筛选需求 | 按城市或拍摄类型筛选 | 列表动态更新 |

### 20.3 摄影师响应需求

前置条件：摄影师已登录，需求处于开放中。

| 步骤 | 操作 | 预期结果 | 讲解点 |
|---|---|---|---|
| 1 | 摄影师点击"我来响应"按钮 | 按钮变为"已响应"，不能重复点击 | 一键意向响应，不立即产生沟通 |
| 2 | 摄影师再次进入该需求 | 显示"已响应"状态 | 后端做了幂等，重复点击不会生成多条记录 |

### 20.4 客户查看并接受响应

入口：个人主页 → 我的意向，或需求管理入口。

| 步骤 | 操作账号 | 操作 | 预期结果 |
|---|---|---|---|
| 1 | 客户 | 进入我的意向 / 收到的响应列表 | 看到摄影师头像、昵称和响应时间 |
| 2 | 客户 | 点击某个摄影师的响应卡，查看摄影师主页 | 可浏览作品集和橱窗 |
| 3 | 客户 | 点击"接受响应" | 系统自动建立与该摄影师的会话，跳转消息页 |
| 4 | 双方 | 进入会话 | 后续流程与路径A（橱窗发起）完全一致：报价→订单→支付→交付→评价 |

讲解点：接受响应不等于下单。真正的订单从摄影师发正式报价、客户确认报价才开始。需求可以收到多个响应，客户只需接受其中一个。

## 二十一、动态广场详细演示

动态广场是用户分享拍摄记录、摄影日记、成片展示的社区功能，支持关注、点赞、查看详情。

### 21.1 发布新动态

| 字段 | 说明 | 演示建议 |
|---|---|---|
| 标题 | 动态标题（必填） | 如"今天去玄武湖拍了秋天" |
| 正文内容 | 文字描述（必填） | 填写一段简短的拍摄感受 |
| 图片 | 上传配图（可多张） | 上传 1-3 张图片展示图片多图能力 |

### 21.2 浏览动态列表

| 演示点 | 操作 | 预期表现 |
|---|---|---|

### 21.3 查看动态详情

| 步骤 | 操作 | 预期表现 |
|---|---|---|

| 2 | 滑动查看图片 | 多张图片可切换预览 |
| 3 | 点击作者头像/昵称 | 跳转到作者公开主页，可浏览其橱窗和动态 |

### 21.4 点赞动态

| 操作 | 预期结果 | 讲解点 |
|---|---|---|

### 21.5 关注 / 取消关注用户

### 21.6 编辑和删除动态

入口：自己的动态卡片右上角菜单（三点图标）。

| 操作 | 预期结果 |
|---|---|
| 点击编辑 | 打开编辑表单，可修改标题和内容 |
| 点击删除 | 弹出确认对话框，确认后动态从列表中消失 |

只有作者本人能看到编辑/删除菜单，其他用户看不到。

| 基本信息 | 头像、昵称、简介、信用分 |

## 二十三、当前演示限制与注意事项

1. 普通聊天图片/附件消息当前不作为演示功能。前端按钮会提示暂未接入，因为后端消息接口目前只接收消息类型和文本内容，没有普通附件文件绑定字段。作品请通过订单交付上传。
2. 服务橱窗的“现在预定”当前进入沟通，不是直接支付。真正的订单从摄影师正式报价、客户确认报价开始。
3. 拍摄开始和拍摄结束依赖订单中的时间字段、页面刷新和后端定时任务，不建议演示时手动伪造状态推进。
4. 自动确认和超期未交付退款需要等待真实时间，现场可通过已有状态订单、状态日志或后端定时任务逻辑说明。
5. 订单争议状态有后端状态和页面展示，但当前前端“平台协助”没有完整发起订单争议表单。评价申诉可以完整演示。
6. 展示授权只允许在订单完成且存在作品后发起。同一订单同一作品不能重复申请授权。
7. 交付上传当前接口一次上传一个文件；如需多张作品，可多次上传形成多条作品记录。
8. 演示尽量使用真实注册账号和真实操作生成的数据。历史种子或本地缓存数据只适合作为兜底展示。

## 二十四、常见问题

**Q：注册时收不到验证码？**  
A：检查垃圾邮件箱；确认后端已启动且日志没有 SMTP 报错。

**Q：切换摄影师身份后页面异常或昵称不对？**  
A：切换后进入个人主页保存一次摄影师资料，系统会初始化摄影师档案。

**Q：8080 端口被占用？**  
A：执行 `netstat -ano | findstr :8080` 找到 PID，再执行 `taskkill /PID <pid> /F` 结束占用进程。

**Q：数据库连接失败？**  
A：确认 MySQL 服务已启动；默认连接配置在 `backend/src/main/resources/application.yml`。如果密码不同，修改配置后重启后端。

**Q：订单页没有上传作品按钮？**  
A：检查当前账号是否为该订单摄影师，以及订单是否已经到交付阶段。拍摄结束前通常不会展示上传入口。

**Q：客户不能确认收货或返修？**  
A：订单必须处于作品待确认，并且已经有作品记录。没有作品记录时不会开放确认或返修。

**Q：摄影师不能发起展示授权？**  
A：订单必须已完成，且存在已交付作品；如果已有待客户处理的授权申请，需要先让客户处理。

**Q：评价按钮不可用？**  
A：订单需要已完成；同一账号同一方向已经评价过后不能重复评价。
