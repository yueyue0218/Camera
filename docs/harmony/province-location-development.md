# 定位与省级地区修复（开发分支）

用户最终确认推送目标：`feature/harmony-c-ui-polish`，适配起点 `6f5163871b02e3ef66579eddeb7f7af3bf11a3c6`。PR base 仍为 `integration/harmony-v1`。先前集成基线修复分支仅作备份，不能覆盖开发分支既有功能。

## 修改与契约

- 唯一 `ProvinceLocation` 保留明确故障类型、原始系统错误码及 `switchState=on/off/unknown`。开关查询的 `801/3301000` 不再变成“系统位置关闭”；`201`、拒绝、`3301100/3301200/3301300`、逆编码不支持与解析失败分别处理。
- 系统位置开关、前台大致位置权限、单次位置、逆编码、省级标准化分阶段检查。撤权及隐私限制立即清缓存并使旧请求失效；前台重检；观察者异常隔离；共享加载状态；页面离开、不可见、手动选择及会话变化后的回调无效。
- 主页与大厅共用 `RegionControl/ProvinceLocation`，手动按钮打开真实 34 项选择器。保留大厅现有风格、价格、时间菜单，保留开发分支 P1 页面和完整服务器隐私同步/撤销流程。未替换 AppClient、Index、HttpClient 或图片服务。
- 统一源目录 `shared/regions/provinces.json`，由 `tools/generate_provinces.py` 生成三端目录：23 省、5 自治区、4 直辖市、2 特别行政区。界面完整中文名；API 和存储仍叫 `cityCode/city_code`，值使用 `JS/ZJ/GD` 等现有 Web 两字母代码。
- 城市仅作历史别名：南京/南京市/NJ/JS/江苏/江苏省及六位数字省级前缀映射为 JS；杭州归 ZJ，深圳归 GD。未知值不默认归省，空筛选为不限，未知历史值仍可原值精确查询；新写入拒绝未知值。没有完整区县代码库，不声称校验所有县级编码有效性。
- 需求/橱窗创建、编辑、草稿恢复、预览及 API 提交边界使用相同规则；地点与服务范围独立保存。数据库 data/count 同谓词、分页前匹配别名，推荐路径使用相同匹配。无表结构或生产数据批量修改。
- 停止浏览器及服务器按 IP 自动推断并回写公开地区；设备定位结果仅缓存在内存中，不写入公开用户资料。诊断不包含坐标、详细地址或凭据。

## 验证与限制

开发分支适配后：Harmony **556/556**，其中定位专项 **25/25**；Web 省级契约 **4/4**。ArkTS `assembleHap --no-daemon -p product=dev` 候选构建通过。后端开发分支回归结果另行记录，不能将先前集成基线测试计数当作本分支结果。

应用版本 1.0.1 / 1000001，`PortraBuild` 可输出构建时传入的 `PORTRA_SOURCE_SHA`（未传时为 uncommitted）。HAP 默认未签名，dev 地址需按验收环境配置；没有安装任何新包。

按用户要求，未打开、操作模拟器。实际 `isLocationEnabled`、系统授权、坐标获取、逆编码能力、手动筛选/发布的设备交互均 **未验证**；旧模拟器安装包 SHA 仍未知。禁止将测试替身通过或 GPS 配置视为真实定位成功。用户自行安装签名后的本分支 HAP，依次验证关闭/重开、首次/拒绝/已授权、撤权再授权、设置返回、超时/逆编码失败、页面角色切换、手动江苏筛选与分页、需求和橱窗发布编辑及草稿恢复。x86 模拟器逆编码可能不可用，必须手动降级并在真机补验。

`harmony/tools/collect-location-diagnostics.ps1` 只读取已有日志白名单，不启动模拟器或定位；保存阶段状态和系统错误码，不保存坐标或凭据。
